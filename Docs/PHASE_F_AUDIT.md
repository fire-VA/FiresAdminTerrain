## EnvironmentBoxes decision

> **KEEP the EnvironmentBoxes module.**

Justification:
1. `EnvironmentBoxController` + `EnvironmentBoxScaler` + `EnvironmentBoxClutterSpawner` have **zero** code references to DELETE-list classes (only stale xmldoc strings).
2. `EnvironmentBoxPatches.cs` has **two** localized surgeries (lines 230–233 in `ClutterSystem_GetGroundInfo_Prefix`, lines 950–990 in `TerrainModifier`/`SetData` postfix) that can be done in <15 minutes. After surgery the module sits cleanly on top of vanilla `Heightmap`, `ClutterSystem`, `TerrainComp`, `TerrainModifier`, plus the new `TerrainTile` (via `GetComponentInParent`).
3. The module's value (placeable env-zone with biome override) is orthogonal to the DirtFloor stack — it does not need a DirtFloor combiner to function.
4. No `BepInDependency` between EnvironmentBoxes and the DirtFloor stack.
